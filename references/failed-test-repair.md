# 续接失败的测试发布

适用情形：迁移已经完成，应用容器运行健康，但最后的公开可用性或版本检查失败。目标是保留已有数据，从失败处继续。第一版支持 PostgreSQL + Prisma，且修复版本的 schema、全部迁移 SQL 和 provider 锁文件与失败版本一致。

AI 负责诊断、修正代码、准备输入、运行固定入口并核验结果。用户只需确认超出现有授权的实际动作；已有测试修复授权不重复询问。生产、迁移中断、结构变更或未知数据现场不走此入口。

## 先确定现场

读取项目状态、实际 `.release.transaction.json` 与当前安装回执。必须是精确绑定的 test `failed/probe` 事务；保留原失败标记、原发布记录、镜像及迁移前快照。容器健康不代表发布成功。

不要删除标记、把记录改为 passed、重跑首装或直接重发普通 TAT。已有失败状态会继续阻断普通发布。

## AI 执行顺序

1. **修复应用并完整构建一次。** 常规 test push 或 `api_trigger_prepare_repair` 均执行完整项目检查及全部镜像构建。后者只准备修复镜像。常规 push 若在失败门禁被挡住，仍可采集已完整通过的构建部分；不要因此重复构建。
2. **必要时升级固定控制器。** 保留旧生成包及旧 accepted installation，用 `scripts/upgrade-controller.py` 先预览再应用。它核对旧、新完整包、原失败事务和快照，只更新测试项目的固定程序、TAT shim 与安装记录。主机策略、Compose、恢复策略、应用文件及空库基线必须保持原字节。首装入口不能代替升级。
3. **更新同一个 TAT 命令及 CI 绑定。** `scripts/configure-tat.mjs` 使用新 spec、`--previous-spec` 和 `--previous-binding`，先预览再 `--apply`。保留命令 ID、执行用户、目录、超时和目标实例；只改经核验的命令内容及名称/描述。使用新的私密 output 保存意图和回执；更新 CNB Secret 后回读。`test.yml` 的 `allow_events` 增加 `api_trigger_repair_test`；如选择准备事件，TCR 文件另增加 `api_trigger_prepare_repair`，仓库与 test 分支限定保留。
4. **导出失败来源并真实恢复。** 标准 `scripts/rehearse-recovery.py` 增加 `--failed-transaction-sha256`，SHA/build 取原失败事务。沿用同一导出 ID 与证据目录续接，在不同的本机 Docker daemon 恢复 PostgreSQL 和声明目录，核对全部实际表、序列及文件，并确认原服务恢复。失败来源记录明确标注公开身份及业务验收未通过。
5. **核验构建证据并签发修复许可。** `scripts/repair-session.py collect` 回读官方 CNB 构建与 stage 日志，核验完整检查、镜像交接记录，以及提交中的生成配置和固定脚本。`scripts/repair-session.py grant` 调用固定的 `grant-test-repair.py`，将这份证据、真实恢复结果、已安装包和迁移文件检查绑定为一次短时 root 许可。详见各子命令 `--help`；输入由 AI 从现有回执取得，不让用户拼写技术参数。
6. **复用镜像完成修复。** 在同一提交的 test 分支通过 CNB 公开 API 触发 `api_trigger_repair_test`，将已验证 `handoff.txt` 作为 `CNB_TEST_REPAIR_BUILD` 环境变量。固定 TAT 使用独立修复请求，在原发布锁下复核现场、保留旧事务、备份当前数据，再原子进入修复事务。已完成且不变的整条迁移命令跳过；正常启动、健康和公开版本检查仍执行。
7. **验收交付。** 真实发布通过才生成候选。再执行项目业务、界面、共存和代表性业务数据恢复验收。失败来源恢复成功只证明当时已有数据可恢复，不代表业务流程已验收。

## 固定入口的边界

本机入口默认预览，不连接云端或改主机。`grant-test-repair.py --apply` 的管理员准备会按精确 digest 拉取迁移镜像，用不启动入口的临时容器读取文件；它不执行 seed 或迁移。许可最长一小时，绑定原事务、原数据、恢复证据、新提交、构建 ID 和全部镜像。

修复只能消费匹配许可，不能在干净主机上退化为普通发布。旧事务和快照保留在历史中，首次版本保守保留修复历史涉及的快照；成功后重复修复请求被拒绝。任一步结果不明时保留证据，按原入口、原输入回读或续接；不要删除目录来强制重试。

控制器升级、TAT 更新、失败来源恢复、完整构建、修复发布和业务验收分别记录状态。每个阶段保存原始回执、摘要、耗时和下一步，后续会话按证据继续，无需重建账号、服务器或流水线。
