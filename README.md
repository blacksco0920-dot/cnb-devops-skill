# cnb-devops-skill

让 AI 帮你接好 CNB（cnb.cool）上的构建、测试部署和正式发布流程，并留下下次能接着用的项目记录。适合用 AI 写代码、希望把项目交付上线的新手，也适合一个人管理多个项目或小团队协作。

默认复用 ecat 实操形成的 **CNB → TCR → TAT → 服务器** 路线：AI 负责接入和项目差异，流水线负责重复执行，你负责必要的账号操作与发布决定。每个项目独立使用同一套 Skill，复用配置和已验收的主机能力，保持权限与数据隔离。

## 整体怎么运行

```text
一次接入：识别项目 → 复用配置和脚本 → 接通账号、镜像仓库及服务器
日常测试：推送代码 → CNB 检查和构建 → 镜像推送 TCR → TAT 部署测试环境
候选发布：测试验收通过 → CNB 自动生成候选 Tag → 生产就绪检查 → 人工审批
正式执行：流水线将同一组镜像部署到生产 → 访问验收与备份恢复核验
```

| 阶段 | AI 做什么 | 你必须配合什么 | 流水线做什么 |
| --- | --- | --- | --- |
| 首次接入 | 读取项目、复用工件、适配服务和环境，准备配置与操作步骤 | 提供查不到的业务选择；完成本人登录、实名及必要控制台配置 | 配置接通后执行检查 |
| 测试与候选 | 发起已授权构建，定位失败，核对结果 | 需要时验收业务效果 | 构建、推镜像、调用 TAT、验证测试环境，成功后生成 Tag |
| 正式发布 | 准备候选说明、核对就绪和恢复条件 | 审批具体候选，决定发布范围 | 通过门禁后部署同一组镜像并记录结果 |
| 下一次发布 | 适配变化、读取当前记录并处理故障 | 完成该次必要的生产审批 | 复用已经接好的流程，无需从头搭建 |

当前已提供从 ecat 提取的测试发布与候选执行包：AI 填一份项目配置，即可生成流水线、固定 TAT 命令及主机工件。一个服务与三个服务的两份样例已完成本地生成和接口验证；FinAgent 三服务已在一台保留预装服务的重置主机上完成测试发布、公网可用性与发布身份核验、自动候选 Tag。生产执行和恢复尚未实现，第二项目的云端复用及完整业务验收尚未验证。入口见[接入步骤](references/bootstrap.md)，固定版本和耗时见[本轮执行包实测](docs/history/2026-09-06-bundle-staging-rehearsal.md)。

## 从这里开始

1. 把本仓库链接发给你使用的 AI 编程工具，说：
   > 请按这个工具支持的方式安装或加载 cnb-devops-skill，并确认你能读取它。
2. 在工具中打开你的业务项目目录，说：
   > 请用 cnb-devops-skill 按标准工作流接入当前项目，优先复用已有 CNB→TCR→TAT 配置和脚本，先列出项目差异，再完成已授权的接入。需要我配合时，明确页面、动作和完成标志。
3. AI 会读取项目现状，完成当前授权范围内的工作，再告诉你已完成什么、实际验证了什么，以及下一步需要做什么。

后续可以直接说：

- **增加项目：**“请为当前项目接入同样的发布流程，复用已验收的主机能力，保留各项目的权限、路由和数据隔离。”
- **接着做：**“请读取当前项目的部署和状态记录，核对最新证据，继续已授权但尚未完成的工作。”
- **发布：**“请把当前项目部署到测试环境并验证。”正式发布时，再明确提出生产发布请求并完成项目要求的审批。

## AI 做什么，你做什么

AI 优先复用现有流水线、部署脚本和固定执行接口，只适配项目差异；缺少工件时明确指出缺口，不把重新开发控制系统混入普通接入。缺少云端条件时，先完成独立的本地工作，并记录尚未接通的步骤。

你负责提供无法从项目中查到的业务选择、需要本人登录的账号或控制台操作，以及项目规定的发布审批。AI 会在确实需要时给出一个具体动作和验收方式；配置文件与技术记录由 AI 整理。敏感值只进入指定的私密存储，不发到聊天或普通代码仓库。

同一个人可以承担多个角色；是否必须由不同人员审批，以项目政策为准。审批是绑定具体候选版本的独立动作，审批通过后仍需执行发布。已经有效授权或验收的工作，在范围不变时继续沿用。

## 交付到哪里算完成

流程覆盖项目接入、构建、测试环境验证、候选版本、合入受控分支、生产就绪检查、审批、生产执行和上线验证。生产使用测试环境验证过的同一组镜像，不重新构建；发生失败时保留现场与恢复记录。客户端打包、商店审核和发布单独跟踪。

本地文件生成、测试通过、云端接通和实际上线是不同结果。AI 应分别报告，只有取得对应环境的运行与访问验证证据后，才确认该环境交付完成。

## 兼容性与验证范围

Skill 入口使用 Agent Skills Markdown 格式；执行包使用 Python、Node.js、Bash 和锁定的腾讯云官方 SDK。AI 工具的最低能力是读取指引、读写项目文件、执行命令及访问 Git/HTTP API；实际脚本依赖按项目安装。不要求 Codex、Computer Use 或浏览器插件。必须本人完成或缺少可用 API 的控制台步骤，由 AI 准备好材料后交给你操作；浏览器自动化只作为可选辅助。

仓库 CI 运行确定性的包测试；[行为场景](tests/skill-scenarios.md)提供当前提示、预期和测试映射，并链接独立的历史评估及其证据限制。这些检查不代表你的云端流水线已经验收。附带的 helper 和 installer 是参考实现，安装前需核对目标主机文件系统与执行接口。

[执行包实测](docs/history/2026-09-06-bundle-staging-rehearsal.md)记录当前包在一个三服务项目上的测试与候选结果，以及实际修复和人工操作成本。[此前部署复盘](docs/history/2026-09-06-live-rehearsal.md)中的生产与异机恢复属于此前项目专用路径，不能替代本包的生产、恢复或多项目验收。
