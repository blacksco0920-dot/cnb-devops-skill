# cnb-devops-skill

**简体中文** · [English](README.en.md)

让 AI 编程助手帮你搭建项目的**测试部署、正式发布和备份恢复流程**。首次接通后，每次更新复用同一套流水线，也能将这套方法应用到你管理的其他项目。

适合用 AI 写代码、希望把项目发布上线的个人开发者和小团队。配置文件、部署脚本和技术记录由 AI 处理，你负责业务选择、必要的账号操作，以及是否正式发布。

**当前为 Preview（预览版）**，适合愿意反馈问题的早期使用者。支持范围和验证结果见下文；全新账号一次接通、跨 AI 工具体验和首次接入耗时仍待验证。版本范围见[预览版说明](docs/releases/v0.2.0-preview.7.md)。

## 它会帮你完成什么

- **第一次接入：**检查项目是否适用，准备配置，接通代码仓库与服务器，完成测试部署。
- **更新项目：**提交代码后自动检查、构建和部署到测试环境，留下可追溯的候选版本。
- **正式上线：**经你确认和项目审批后，将测试通过的同一版本部署到生产环境，核验实际业务。
- **备份恢复：**明确数据范围，实际导出并在隔离环境恢复，核对数据库和备份文件。
- **中断后继续：**AI 读取已保存的进度，从可验证的断点继续，保留已经完成的配置和导出。

```text
准备账号与服务器 → AI 接通流水线 → 验收测试环境 → 确认正式发布 → 上线与恢复验收
                       ↑
                 后续更新复用这套流程
```

默认使用腾讯云服务：**CNB** 托管代码并运行自动任务，**TCR** 保存构建好的应用镜像，**TAT** 将发布指令送到服务器。项目需要哪些服务、如何构建和验收，由 AI 从你的代码中识别并适配。

## 开始前需要什么

| 准备项 | 你需要知道什么 |
| --- | --- |
| 项目源码 | 在 AI 编程工具中打开项目。AI 检查构建、运行和数据存储方式，指出需要补齐的部分 |
| AI 编程工具 | 能读取 Skill、读写项目文件、执行命令，以及访问 Git 和网络 API；接口不限定品牌，当前实操主要使用 Codex |
| 本地执行环境 | 当前实操使用 macOS；完整流程需要类 Unix 环境、Node.js 22、Python 3.12+、Git/SSH。恢复验收还需要可通过本地 Unix socket 访问的 Docker。AI 先检查并准备依赖 |
| CNB 与腾讯云账号 | 能管理本次项目和云资源；登录、实名、验证码等本人操作需要你完成 |
| 服务器与域名 | 完整双环境路线使用两台独立服务器；仅接测试可先提供测试服务器和域名，生产目标就绪后再接。已有服务器先检查现状 |

当前首装入口适用于使用 **PostgreSQL 16** 的可容器化 Web 应用与服务，目标为 Ubuntu 24.04 / Linux amd64，使用 Docker Compose，可选 Redis 7。**无数据库项目和其他数据库暂不支持这条固定路线**；AI 会先检查并说明限制，不要求你为了部署增设数据库。其他系统或复杂主机拓扑需先评估，见[接入说明](references/bootstrap.md)。云资源费用由对应平台收取。

本地执行环境与云服务器是两回事。**原生 Windows 不支持当前完整执行入口**；Linux 桌面、WSL 和远程开发环境尚未完成端到端首接验证，需先核对文件权限、登录回调和 Docker 条件。新建镜像仓库的固定入口目前仅支持腾讯云 TCR 个人版广州地域；已有部署是否可复用由 AI 检查。

AI 优先复用官方登录或已有初始化凭据。CNB 默认登录缺少创建权限时，AI 会准备准确选项，引导你一次创建并安全导入短期初始化令牌，再继续自动配置；必要的密钥文件保存仍在官方网页完成。你无需学习命令或权限配置，也不需要浏览器自动化插件；AI 会准备支持隐藏输入的终端或工具已有的安全导入入口，没有可用入口时集中交接必要网页操作。

## 怎样开始

1. 把本仓库链接交给 AI 编程工具，说：
   > 请按当前工具支持的方式安装或加载 cnb-devops-skill，确认能读取 SKILL.md，并告诉我实际加载的位置。
2. 在工具中打开你的业务项目目录，说：
   > 请使用 cnb-devops-skill 检查当前项目是否适用，为它接通测试环境的自动部署流程，并验证访问和基本业务。需要我提供信息或操作时，请告诉我具体动作。正式发布等我确认后再进行。
3. 按 AI 提示完成必要操作，打开交付的测试地址检查业务。准备上线时，再明确提出生产发布请求，确认具体候选版本并完成审批。

安装时优先指定已发布 Tag `v0.2.0-preview.7`，记录完整提交和实际加载位置。可下载该 Tag 的源码归档，或按该 Tag 浅克隆，只取得当前发行快照；完整克隆仍会带回已有公开历史。具体命令见[版本说明](docs/releases/v0.2.0-preview.7.md)。

同一个人可以按项目政策承担多个角色。你不需要手写部署配置或整理技术回执；敏感值只保存到指定的私密存储，不发送到聊天或普通代码仓库。

## 完成后应拿到什么

- **可访问的环境：**测试或生产地址，以及实际完成的访问和业务检查结果。
- **可追溯的发布：**代码仓库、流水线与候选版本链接，当前环境运行的版本。
- **能接着用的项目记录：**项目中的部署说明和当前状态，下一次换 AI 会话也能继续。
- **明确的恢复与维护信息：**备份范围、实际恢复结果或未完成项，以及凭据有效期和后续维护事项。

只完成测试环境时，就按测试范围交付。文件生成成功不等于已经上线；恢复验收也只覆盖已声明并实际验证的数据。缺少的条件、失败的步骤和未验证的范围会单独记录。

## 下次怎么用

| 你的需要 | 可以直接对 AI 说 |
| --- | --- |
| 更新项目 | 请把当前改动部署到测试环境并验证 |
| 接着上次做 | 请读取项目的部署和状态记录，继续已授权但未完成的步骤 |
| 增加另一个项目 | 请用这个 Skill 为当前项目接通同样的流程，核对它自己的账号、服务器和数据范围 |
| 正式发布 | 请准备当前候选的生产发布，说明版本和影响，按项目要求完成审批后上线 |
| 核对已发布版本 | 请只读核对这次发布结果，检查已声明的共存和验收范围，并更新现有项目状态 |

多项目复用指每个仓库使用同一套方法和执行程序。希望复用已有服务器时，可以直接告诉 AI「在这两台服务器上追加项目，保留已有项目」。AI 先核对容量、权限、路由和数据隔离；符合条件的使用[同主机追加流程](references/native-caddy-shared.md)。已验证同一所有者两个项目的双环境接入，以及第三项目的独立测试接入；持续负载与跨信任租户隔离仍待验证。已有发布程序的版本升级也需要单独检查，不能重复首装来覆盖。

## 验证与技术参考

标准路线已有真实项目的双环境发布、业务检查和离机恢复记录。实测前提、范围和未验证项见[公开验证摘要](references/validation-summary.md)；个案耗时不作为任意新项目的交付承诺。

官方登录、CNB 私有/Secret 仓库创建、构建设置、腾讯云固定命令和专用身份已有 [API 实测](references/validation-summary.md#api-onboarding)。生产、恢复和测试收尾使用固定入口，保存证据并支持重复续接；用户无需整理技术回执。

最近一次[陌生项目接入](references/validation-summary.md#unfamiliar-project)完成了共享主机测试部署、业务与数据库恢复。针对该轮仍需临时编排的工作，又固化了 [TCR 初始化与测试收尾](references/validation-summary.md#tcr-closeout)，已用现有真实资源验证只读回查与状态同步。新 TCR 入口的全新资源创建、全新账号自动初始化和整体提速仍待实测；TAT 发布身份的密钥签发仍由 AI 按文档调用 API 完成。

以下内容主要供 AI 按需读取，使用者不必逐篇学习。技术契约维护同一套文件，中英文首页都指向它们；AI 按你的语言解释当前操作：

- [SKILL.md](SKILL.md)：按任务选择执行入口。
- [标准工作流](references/standard-workflow.md)：阶段顺序、职责与复用工件。
- [接入说明与完整示例](references/bootstrap.md)：生成配置、安装主机、发布与恢复。
- [账号与 API 接入](references/api-onboarding.md)：官方登录、自动配置及确实需要本人操作的边界。
- [镜像仓库初始化](references/tcr-setup.md)：AI 准备 TCR 私有仓库、推送和拉取身份，保存可续接的配置进度。
- [项目接续](references/project-adoption.md)与[人员配合](references/human-handoffs.md)：保留进度，只补当前缺口。
- [发布后收尾](references/post-release-closeout.md)：只读回查发布、按声明核对共存，并更新本地状态；历史发布成功与当前运行、业务和恢复验收分别记录。

## 试用反馈

遇到问题时，可以直接让 AI：

> 请保留当前进度，整理一份适合提交 GitHub Issue 的脱敏反馈，说明 Skill 版本、本地系统和 AI 工具、卡住的阶段、预期与实际结果，以及我实际需要做的操作。

检查后通过 [GitHub Issues](https://github.com/blacksco0920-dot/cnb-devops-skill/issues)提交，中文或英文均可。不要上传密钥、完整配置、备份或整段原始日志；AI 只提取必要的错误信息。版本、安装和维护约定见[预览版说明](docs/releases/v0.2.0-preview.7.md)。
