# cnb-devops-skill

让 AI 编程助手帮你搭建项目的**测试部署、正式发布和备份恢复流程**。首次接通后，每次更新复用同一套流水线，也能将这套方法应用到你管理的其他项目。

适合用 AI 写代码、希望把项目发布上线的个人开发者和小团队。配置文件、部署脚本和技术记录由 AI 处理，你负责业务选择、必要的账号操作，以及是否正式发布。

## 它会帮你完成什么

- **第一次接入：**检查项目是否适用，准备配置，接通代码仓库与服务器，完成测试部署。
- **更新项目：**提交代码后自动检查、构建和部署到测试环境，留下可追溯的候选版本。
- **正式上线：**经你确认和项目审批后，将测试通过的同一版本部署到生产环境，核验实际业务。
- **备份恢复：**明确数据范围，实际导出并在隔离环境恢复，核对数据库和备份文件。

```text
准备账号与服务器 → AI 接通流水线 → 验收测试环境 → 确认正式发布 → 上线与恢复验收
                       ↑
                 后续更新复用这套流程
```

默认使用腾讯云服务：**CNB** 托管代码并运行自动任务，**TCR** 保存构建好的应用镜像，**TAT** 将发布指令送到服务器。项目需要哪些服务、如何构建和验收，由 AI 从你的代码中识别并适配。

## 开始前需要什么

| 准备项 | 你需要知道什么 |
| --- | --- |
| 项目源码 | 在 AI 编程工具中打开项目。AI 检查构建、运行和数据存储方式，指出需要补齐的部分 |
| AI 编程工具 | 能读取 Skill、读写项目文件、执行命令，以及访问 Git 和网络 API；不限定品牌 |
| CNB 与腾讯云账号 | 能管理本次项目和云资源；登录、实名、验证码等本人操作需要你完成 |
| 服务器与域名 | 完整双环境路线使用两台独立服务器；仅接测试可先提供测试服务器和域名，生产目标就绪后再接。已有服务器先检查现状 |

当前首装入口支持 Ubuntu 24.04、Linux amd64、Docker Compose、PostgreSQL 16 和可选 Redis 7，适用于可容器化的 Web 应用与服务。其他系统、数据库或复杂主机拓扑需要先评估差异，见[接入说明](references/bootstrap.md)。云资源费用由对应平台收取。

AI 优先复用官方登录或已有初始化凭据。CNB 默认登录缺少创建权限时，AI 会准备准确选项，引导你一次创建并安全导入短期初始化令牌，再继续自动配置；必要的密钥文件保存仍在官方网页完成。你无需学习命令或权限配置，也不需要浏览器自动化插件；AI 会准备支持隐藏输入的终端或工具已有的安全导入入口，没有可用入口时集中交接必要网页操作。

## 怎样开始

1. 把本仓库链接交给 AI 编程工具，说：
   > 请按当前工具支持的方式安装或加载 cnb-devops-skill，确认能读取 SKILL.md，并告诉我实际加载的位置。
2. 在工具中打开你的业务项目目录，说：
   > 请使用 cnb-devops-skill 检查当前项目是否适用，为它接通测试环境的自动部署流程，并验证访问和基本业务。需要我提供信息或操作时，请告诉我具体动作。正式发布等我确认后再进行。
3. 按 AI 提示完成必要操作，打开交付的测试地址检查业务。准备上线时，再明确提出生产发布请求，确认具体候选版本并完成审批。

同一个人可以按项目政策承担多个角色。你不需要手写部署配置或整理技术回执；敏感值只保存到指定的私密存储，不发送到聊天或普通代码仓库。

## 完成后应拿到什么

- **可访问的环境：**测试或生产地址，以及实际完成的访问和业务检查结果。
- **可追溯的发布：**代码仓库、流水线与候选版本链接，当前环境运行的版本。
- **能接着用的项目记录：**项目中的部署说明和当前状态，下一次换 AI 会话也能继续。
- **明确的恢复与维护信息：**备份范围、实际恢复结果或未完成项，以及凭据有效期和后续维护事项。

只完成测试环境时，就按测试范围交付。文件生成成功不等于已经上线；恢复验收也只覆盖已声明并实际验证的数据。缺少的条件、失败的步骤和未验证的范围会单独记录。

## 下次怎么用

| 你的需要 | 可以直接对 AI 说 |
| --- | --- |
| 更新项目 | 请把当前改动部署到测试环境并验证 |
| 接着上次做 | 请读取项目的部署和状态记录，继续已授权但未完成的步骤 |
| 增加另一个项目 | 请用这个 Skill 为当前项目接通同样的流程，核对它自己的账号、服务器和数据范围 |
| 正式发布 | 请准备当前候选的生产发布，说明版本和影响，按项目要求完成审批后上线 |

多项目复用指每个仓库使用同一套方法和执行程序；多个项目共用一台服务器需要另外核对资源、权限、路由和数据隔离。已有发布程序的版本升级也需要单独检查，不能重复首装来覆盖。

## 验证与技术参考

标准路线已有真实项目的双环境发布、业务检查和离机恢复记录。实测前提、范围和未验证项见[验证记录](docs/history/README.md)；个案耗时不作为任意新项目的交付承诺。

新增接入方案已实测官方登录、已有 CNB 仓库识别，以及腾讯云固定命令和专用身份的配置与复用。针对 CNB 默认登录缺权，已补齐私密初始化令牌入口；该入口的本机检查不等于真实创建验收，完整自动初始化及首次接入耗时仍待验证。OIDC 未切换为默认发布方式。见[API 实测结果](docs/history/2026-09-07-api-live-validation.md)和[初始化令牌入口](references/api-onboarding.md#cnb-bootstrap-token)。
