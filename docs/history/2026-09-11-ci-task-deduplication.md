# CI 重复任务消除实测

## 范围与改动

2026-09-11 在第二个已接入项目 FinAgentCrm 上验证项目检查阶段的重复编译。应用提交为 `c304b603a2bd184127c05ee17d2d332ef8417c08`，使用已安装的 `0.2.0-preview.5` 部署包；本轮没有升级控制器、修改业务、迁移或 Dockerfile，也没有生产发布。

根 `check` 原先分别执行 lint、typecheck、build 三个任务图；在 CI 强制重跑的条件下，上游共享包被多次编译。项目改为一次 `turbo run lint typecheck build`，并显式让 Web typecheck 等待自身 build：它会读取构建生成的 `.next/types`，不能与清理、生成该目录的操作并发。

合并前后各工作区任务的脚本命令与检查集合相同；强制执行保留。四个共享包的 build 从各 3 次降到各 1 次，`check` 的实际任务执行次数从 **23 次降到 15 次**。API 测试服务启动前的镜像内预构建仍有独立用途，没有删除。

## 沉淀与边界

通用指导进入 [bootstrap](../../references/bootstrap.md)：先用真实阶段时间定位问题，再核对重复任务与生成物依赖，最后用实际执行次数和同条件计时验收。特定构建器配置留在项目中；其他项目不需要访问本项目或旧会话。

本轮只验证检查任务去重及其测试发布结果。先前生产、业务、页面、共存与恢复证据仍归属于原提交，不以它们替新候选补签完整验收。镜像依赖层调整留待单独测量；未验证普遍提速、新账号首接时限或持续负载。
