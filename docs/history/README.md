# 验证记录与来源

本目录供维护者了解能力来源、实测范围和未完成项。日常使用从[项目首页](../../README.md)开始，AI 执行从[标准工作流](../../references/standard-workflow.md)开始；无需先读历史项目或旧会话。

## 已经验证了什么

[双环境完整演练](2026-09-07-complete-rehearsal.md)记录同一已适配业务项目的三轮真实重装：测试部署、自动候选、批准后同镜像生产、业务检查，以及 PostgreSQL 与声明上传目录的离机恢复。记录保留真实项目名、固定提交、流水线和回执摘要，便于追溯。

第 3 轮完成上述范围用时 **28.74 分钟**，没有修改 Skill 或失败重试。这个结果有明确前提：应用此前已完成容器化、迁移、身份探针和验收脚本适配；账号权限、仓库、镜像仓库、固定命令、Secret、域名等接入材料已经准备，可复用仍有效的配置、凭据及缓存。两台主机在该轮真实重装，但没有从零注册全部账号、配置全部云资源或首次分析陌生项目。

因此，这个耗时说明固定流程在已准备条件下可以较快复用，不能作为任意新项目的交付时限。首次项目适配、依赖下载、镜像缓存和本人验证都会影响时间；各轮原始耗时与等待范围见记录。

用户在三轮后结束本阶段。第 4 轮在云端接受重装前取消，没有发生第 4 次已接受的云端重置；不继续等待验证或将准备工作计为完整轮次。连续两轮无需修复的快速成功，以及第二个项目的云端接入，仍未得到验证。

## 如何区分证据

| 材料 | 能说明什么 | 不能代替什么 |
| --- | --- | --- |
| [完整演练](2026-09-07-complete-rehearsal.md) | 固定版本、指定环境的真实部署与恢复结果 | 任意项目、当前新生成工件或所有业务功能的验收 |
| [早期可复用包测试](2026-09-06-bundle-staging-rehearsal.md) | 早期包的测试部署和候选路径 | 生产、完整业务与恢复验收 |
| [早期项目专用演练](2026-09-06-live-rehearsal.md) | 专用实现的历史结果和问题 | 当前标准执行包的成功证据或操作入口 |
| [官方登录与 API 实测](2026-09-07-api-live-validation.md) | 官方登录、已有仓库识别、TAT/CAM 配置与复用；CNB 创建缺权的实际边界 | 新账号完整自动初始化、新版运行包的部署与恢复验收 |
| [包内检查](../../tests/)与[行为场景](../../tests/skill-scenarios.md) | 配置生成、执行接口和门禁回归；AI 行为的评估范围 | 实际云端部署、真实业务或公开推广的耗时承诺 |
| [工件清单](../../assets/cnb-tcr-tat/bundle.json) | 版本、文件摘要及其关联的验证记录 | 更新文档后自动确认新工件或升级现有主机 |

完整演练的业务范围包含真实 OCR，但部分外部模型调用使用模拟实现；未涵盖完整前端操作、租户隔离或生产负载。恢复覆盖数据库与声明上传目录，不覆盖整机、运行秘密或未声明的存储。活动版本升级及第二项目共享主机仍需独立验证。
