# 首次真实部署复盘

2026-09-06。目标是让 AI coding 新手在新 CNB 账号和两台腾讯云服务器上，完成一个业务项目从构建、测试部署到生产发布、访问验证和数据库恢复的全过程。操作者按既有授权执行；本人登录、身份验证及必要业务选择由项目负责人完成。

## 实际完成的范围

| 环节 | 实际结果与证据 |
| --- | --- |
| 构建与测试环境 | CNB 构建生成五个固定 digest 镜像；测试主机运行与公网业务分别验收。 |
| 候选与生产 | 不可变候选绑定应用、控制器和完整镜像集；原生审批、独立执行授权及固定 TAT 命令完成生产发布；生产复用测试镜像。 |
| 生产核验 | CNB 回执、独立 TAT 查询、主机运行证据、公网 TLS/路由与受控合成业务检查分别取得。 |
| 业务备份 | 业务验收后单次导出 PostgreSQL 备份，源端导出前后指纹一致；实际下载并验证两端摘要。 |
| 异机恢复 | 本机隔离 PostgreSQL 从空库单次恢复成功；12 张表的行数和内容指纹与源端一致；容器停止，备份和卷保留。 |

原始日志、备份、权限记录和回执由项目负责人保管在私密证据目录，业务项目的 `docs/PROJECT_STATUS.md` 索引具体位置、时间和摘要。本公开记录仅保留脱敏结论；未随包发布原始证据，外部读者不能仅凭本文件独立核验此次执行。它不是在最终 Skill 修订上重新运行的端到端评估。

## 暴露的问题及本次修正

| 实操问题 | 处理与规则归属 |
| --- | --- |
| 人工审批后，平台新增的 annotation 被候选校验误拒绝 | 项目控制器仅接受该审批配置实际产生的精确键值，保留严格候选校验；创建新候选，未移动旧 Tag。对应 [CNB 部署页面](../../references/cnb-deployment-ui.md#candidate-tag)。 |
| 用户多次找不到“授权确认” | 明确区分聊天范围确认、控制台本人验证、候选审批；沿用有效授权，AI 先备齐执行材料。对应 [人员交接](../../references/human-handoffs.md)。 |
| 新服务器带有预装服务；构建环境能拉镜像，主机却不一定能拉 | 先确认端口、资源及所有权，保留用户要求保留的服务；逐主机验证 registry 访问并固定依赖镜像。对应 [主机分类](../../references/project-adoption.md#host-and-account-classification)。 |
| “禁止另建仓库”的绝对规则与已授权控制仓库冲突 | 默认业务仓库，尊重有依据的项目专用控制仓库；不自动扩展为全局运维平台。对应 [项目接入](../../references/project-adoption.md)。 |
| 独立控制仓库仍可被本次应用事件的内建令牌写入 | 受限写探针及独立回读证明该配置下的权限；本项目采用 CI 外签名和受保护主机验签。不能推定所有 CNB 事件都如此，也不能把签名或分仓设为通用前提。对应 [执行权限](../../references/release-safety.md#credentials-and-execution)。 |
| 下载提示成功，但本机未拿到文件；另一下载事件超时，文件其实已到达 | 以实际目的文件、权限、大小和两端摘要验收，核实后再决定是否重试。对应 [私密文件传输](../../references/human-handoffs.md#private-file-transfer)。 |
| 发布前空库快照易被误当成业务恢复证明 | 保留初始快照，另用验收后的业务备份完成隔离恢复和比对；按存储类型说明范围。对应 [备份与恢复](../../references/release-safety.md#backup-and-restore-acceptance)。 |
| 成功后状态文档仍描述待部署；临时凭据存在到期维护任务 | 更新业务项目的当前索引，保留阶段回执原件；记录凭据实际截止、消费位置及续期责任。对应 [恢复工作](../../references/project-adoption.md#resume-an-existing-project) 与 [凭据回执](../../references/human-handoffs.md#secret-receipt)。 |

## 尚不能据此宣称的能力

- **真实客户可用：**应用的租户授权缺陷仍存在。关闭公网注册仅限定演练入口，不能修复已有账号的数据权限；外部 AI 集成仍使用 mock，未完成真实服务验收。页面还保留旧验收横幅及与注册限制不一致的入口。
- **完整灾备：**只完成 PostgreSQL 恢复，未证明上传文件、Redis、OCR 缓存、外部存储或整机恢复，也未建立持续备份和 RPO/RTO 达标记录。
- **新手快速复现：**本次由 AI 持续适配并接受人工协助，仍有多次浏览器交接和项目专用脚本工作。成功走通不等于已证明低操作成本或稳定耗时。
- **多项目隔离：**真实案例只覆盖一个项目、两个环境。仓库内的多项目场景仍需第二个真实项目验证，尤其是共享能力复用和禁止跨项目访问。

## 后续验证优先级

1. 在真实客户使用前完成应用授权修复、真实外部集成验收和入口文案清理；这些属于业务项目，不放入通用 Skill。
2. 由负责人完成临时凭据到期台账和续期演练，验证每个消费位置；补齐持续备份及业务要求的恢复范围。
3. 用第二个项目、新会话重新接入，记录人工介入次数、阶段耗时、续接时缺失信息和实际隔离结果。只有再次出现的适配工作，才考虑提炼为更通用的工具。

本次 Skill 修订集中修正规则与证据边界，未新增运行时、全局控制仓库或自动发布工具。仓库包检查负责发现格式、链接及契约回归，不能替代上述真实验证。
