# 独立会话的首次使用验证

## 范围与方法

本轮验证 AI 能否只凭指定 Skill 和项目文件完成已授权的本地工作。固定版本为 `e86b2967de5bb1bbd29e534aed1242af6bf7aee3`，运行包仍为 `0.2.0-preview.5`；开始前将该提交复制为只读快照，224 个文件与 Git 对象一致。

使用仓库现有的 [首次接入样例](../../tests/fixtures/skill-usage/novice-local-pipeline.json)和[第二项目样例](../../tests/fixtures/skill-usage/second-project-reuse.json)，各自展开在独立目录。两个新建 Codex 会话并行执行，不 fork 维护会话，也不提供验收答案、真实项目配置或凭据。第三个新会话取得第一份已完成的项目副本，验证只依赖项目文件的续接。

执行者只读指定 Skill 的当前操作资料，不读取 tests、历史报告、计划、其他会话或真实项目；只可修改对应样例并运行原有 Python 检查，不可联网、调用 Docker、操作云端或生产。该边界由任务指令和只读文件权限约束，不是独立操作系统沙箱。会话仍使用同一 Codex 宿主的工具与全局设置，因此不代表跨 harness 验证。

两份样例都是无数据库、无持久卷的 Python HTTP 服务，外部绑定为未知。它们适合检验边界判断和本地交接，不能覆盖当前 PostgreSQL 标准路线的完整首次部署。

## 已观察到的问题与边界

1. **无数据库项目不在当前固定运行包的能力内。** 两个会话都独立定位到 schema、生成器和主机程序强制 PostgreSQL，均未擅加数据库或重写发布核心。主审从源码确认了该结论。补齐云参数、只省略迁移/恢复或仅修改 schema，都不能让当前运行核心支持无数据库发布。入口应尽早说明这一前提，避免读取大量实现后才发现不适用。
2. **生成器依赖未就绪是本轮环境限制。** 两次真实 `prepare-project.py --diff` 都在缺少 PyYAML/jsonschema 时退出，尚未进入项目 schema 校验；禁止联网安装是样例授权边界。数据库限制来自静态源码核验，不能将它冒充本次生成器报错，也不能把未安装依赖直接当作脚本缺陷。
3. **第二项目的最终交接仍有技术负担。** 最终回复要求补齐 B 专属接入记录，交接文档又以配置回执/provisioning 状态作为完成条件。虽然文档写着由 AI 整理，这仍不够像新手可以直接执行的一个动作。需要优先解决兼容性，再由 AI 准备明确的页面或最小信息请求；不应先让用户理解、寻找一整套技术记录。
4. **手工阻断草稿制造了后续生成冲突。** 两个执行者都手工创建候选事件和 `.cnb/tag_deploy.yml`，没有生成器的归属锁。主审使用现有 `merged_pipeline` 与完整示例进行纯内存复现，两个候选事件都触发 `CNB event already exists without ownership evidence`；审批页也与生成器托管输出不同，会触发受管文件漂移。当前不会因此误部署，但后续取得兼容方案仍要清理这些自建障碍。B 的说明已提示届时移除片段，这种清理成本仍然可以避免。此复现不执行完整生成器，不表示无数据库模式已支持。
5. **仅本地准备仍消耗较多阅读与产物整理。** 两个执行者分别自报读取 12、16 份 Skill 文件，可见记录包含 24、28 次命令执行，以及全文读取后的重复分段读取。分别留下 13、14 个项目文件（不含评估记录），但没有可部署的固定包。后续应先完成适用性判定，命中不支持范围时收敛为必要准备和一份简短交接，避免展开无效的完整发布草稿。

## 首轮建议

- 在入口前置准确的支持范围和依赖预检；无数据库能力是否扩展需单独确定实现范围，不能通过放宽校验伪装支持。
- 生成器受管文件只能由固定入口产生；受限草稿不占用将来的托管事件/审批页位置，不伪造 generation lock。
- 修正第二项目的用户交接，只让人补无法发现的信息或完成必要本人操作。
- 增加一份真正符合当前 PostgreSQL 标准路线的小型接入样例，验证固定生成器的顺畅路径；不要把本轮两次正确阻断当作标准首次接入成功。
- 只对实际修正的场景做新的独立会话复核。真实无浏览器 Secret 保存、先测试后补生产的顺序生成、跨 harness 和陌生项目云端首接仍未验证。

## Secret 材料与用户交接续验

本项使用 `1b90c87` 的只读快照、合成仓库事实及两项明确假值。独立准备会话只读当前操作资料，不读取历史项目、评估答案或旧会话，也不访问网络、云端或真实凭据。消费者为普通脚本任务，限定一个应用仓库的 `test` 分支 `push` 事件。另一会话只收到用户交接指引及其链接的假材料，预检能否定位、取用和理解完成条件；这部分属于文字与文件审查。
