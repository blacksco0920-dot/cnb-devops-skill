# 官方登录与 API 配置实测

2026-09-07。结论：**腾讯云配置与复用通过；CNB 默认 CLI 登录未通过仓库创建。整个新账号自动接入方案尚未通过。** 本轮从 `23287a0` 的接入实现开始，遇到真实返回差异后作最小修复，运行包更新为 `0.2.0-preview.3`。日常入口见[账号与 API 接入](../../references/api-onboarding.md)。

## 实测范围与结果

沿用已有业务项目的两个测试用云实例、组织和仓库，本机此前没有本方案的官方 CLI 登录记录。使用固定工具版本：`@cnbcool/cnb-cli@1.15.18`、`tccli==3.1.162.1`、`requests==2.32.5`、`six==1.17.0`；云 SDK 使用包内锁文件。

| 验证项 | 真实结果 |
| --- | --- |
| CNB 与腾讯云首次官方登录 | 两项均成功；人分别完成官方页面授权，无手工创建、复制密钥或向聊天发送凭据 |
| 腾讯云临时会话 | 通过官方 profile 刷新/导出完整临时三元组，API 确认所属账号；文件保持私密 |
| CNB 已有资源 | 读取组织 Owner、私有业务仓库和构建开关；通过组织列表确认 Secret 仓库，配置器最终返回 `unchanged` |
| CNB 新建私有验证仓库 | 创建被 `403/10023` 明确拒绝，缺少 `group-resource:rw`；回查确认未创建，pending 已安全解除 |
| CNB 新建 Secret / 修改构建开关 | 前序创建失败，本轮未执行；不能将接口存在计为实测成功 |
| 云实例与 TAT | 找到两台 RUNNING 实例；配置器对测试目标确认 Linux Agent Online，创建一条独立验证命令并完整回读 |
| TAT 重复运行 | 原命令复用；命令 ID、正文和绑定摘要不变，只更新每次查询的请求回执，无 Invoke |
| CAM 专用身份 | 创建无控制台登录的测试专用用户、单实例/固定命令策略及关联，回读权限、组和密钥状态；第二次输出完全一致 |

TAT/CAM 新增资源仅用于本轮验证：一条尚未执行的固定命令、一名无 AccessKey 的专用用户和一份关联策略；本机私密回执记录其准确身份。没有新增服务器、重装、调用部署命令、改变原业务流水线或发布生产。配置回执明确 `deployment_ready: false`。原部署继续使用已安装版本，新运行包没有自动替换活动主机程序。

## 从失败中修正的行为

1. **仓库读取入口。** Secret 单仓库详情返回“Secret repos do not support token access”；公开组织仓库列表可以读取元数据。配置器改为完整分页、精确身份核对，并记录父组织权限依据，保留列表的 Unknown 角色事实。
2. **确定拒绝与未知结果。** 原配置器把明确权限拒绝也持久锁在未知创建状态。现在只有标准拒绝且回查确认不存在时才释放 pending；网络失败、5xx 和回查不明继续阻止盲目重建。
3. **缺权的可行动提示。** 对标准 `10023` 返回稳定 `CNB_SCOPE_REQUIRED` 与白名单 `required_scopes`，不暴露任意服务端错误正文。文档要求停止相同权限下重试，必要的 CNB 创建/设置集中交接。
4. **TAT 新旧参数表示。** 实际创建使用 `DefaultParameterConfs`，回读将旧 `DefaultParameters` 留空。配置器和发布客户端接受这一精确表示；参数冲突、额外参数、错误默认值仍拒绝。

对应回归覆盖实际响应形态、拒绝后续接、Secret 分页与权限依据，以及参数冲突在 Invoke 前拦截。它们验证修复，不代替云端部署或业务验收。

## 对“低操作成本”的结论

这轮用户完成了两项本人授权，AI 未操控浏览器，也没有要求复制凭据。腾讯云初始化路径可复用官方登录和 API，后续无需逐项配置 TAT/CAM 控制台。

CNB 默认 CLI 登录的创建权限缺口尚未打通。固定版 CLI 没有 `login --scope`；公开授权管理文档没有增权操作，自建 OAuth 应用需要平台登记审核。Owner 身份、接口公开与实际令牌权限是三件不同的事。[CLI 文档](https://docs.cnb.cool/zh/develops/cnb-cli.html)、[用户授权说明](https://docs.cnb.cool/zh/oauth/user.html)、[应用登记说明](https://docs.cnb.cool/zh/oauth/developer.html)

当前可用交接是由 AI 准备准确名称、类型、设置和官方页面，合并必要的 CNB 创建与 Secret 保存动作；已有批准的组织集成可沿用其实际写权限。不能宣传“只登录两次即可全自动接入”，也不要求每个小白用户自行登记 OAuth 应用。

Secret 文件写入、长期发布密钥签发、OIDC、完整新账号流水线及新一轮部署/恢复均不在本轮通过范围。耗时包含接口诊断和 Skill 修复，没有形成可对外承诺的首次接入指标。完整接入和第二项目复用仍需分别验收。

私密验证目录保留登录之外的配置 spec、云端请求回执、创建状态和重复运行结果。公开记录只保留结果与版本；不包含账号 ID、服务器 ID/地址、密钥或完整环境文件。

## 2026-09-08：真实 PAT 续验通过

使用 `b25b5fe` 的 `configure-cnb.mjs`、固定官方 CLI `1.15.18` 及显式 `--token-file`，在既有业务项目的组织下创建两个独立验证仓库。全过程沿用上次创建失败后的原 spec 和 journal；开启开关时仅使用将 `auto_trigger` 改为 true 的 spec。未修改执行器或部署运行包。

| 验证项 | 真实结果 |
| --- | --- |
| 私密导入与身份选择 | 用户通过无回显终端保存新 PAT；文件为本人所有的 0600 普通单链接文件。执行回执均为 `authentication: token_file` |
| 创建前读取 | 新 PAT 可读取同组织已有业务仓库的 Owner/Private 信息及四项构建设置；预览确认两个验证仓库尚不存在 |
| 新建私有与 Secret 仓库 | 两者均创建成功，回读路径、ID、类型；Secret 元数据通过父组织列表核对 |
| 构建设置 | 私有验证仓库的 `auto_trigger` 为 false → true → false；另三项始终保持 true/true/false，开启及关闭计划仅含这一项变更 |
| 重复运行 | 原 spec 再执行返回 `unchanged`、`plan: []`，两库 ID 全程相同，原 journal 两项均为 `verified` |

重复运行无云端 POST/PUT 的结论来自回执与执行器写入计数逻辑，没有独立网络抓取记录。配置器仍可更新本机 journal，不能把“资源未变”描述为“本地没有任何写入”。

四次配置器执行分别为 4.286、2.537、2.628、1.767 秒，合计 **11.218 秒**。此数仅计拿到正确 PAT 后的创建、开关开启、关闭及复用，不含前置读取、人工创建与导入、排障或文档整理；不是首次接入或部署耗时。

### 本轮暴露的交接问题

首枚令牌的截图显示“仅应用于”既有业务仓库；该 PAT 创建被 403 拒绝，回查确认未创建。随后对已有私有仓库及构建设置的只读诊断分别得到 `403/10023`，缺少 `repo-basic-info:r`、`repo-manage:r`。这确认了读取权限不足，但不能仅凭这两项只读拒绝推断创建接口的具体拒绝原因。

AI 通过两张非秘密页面截图核对实际表单后，明确区分“指定组织”与“指定仓库”，并把下方三项权限与“常见场景”卡片分开指引。用户第二次创建并安全导入后，上述云端验证通过；未重新登录、删 journal 或重复创建未知结果的资源。接入文档已补上这些具体交接要求。

本轮实际有两次令牌创建与导入、两张截图交接，不能宣传人工步骤已经压缩为一次。第二枚令牌按“指定组织、7 天”的要求交接，但没有取得其创建后范围/有效期的独立回读；API 成功只证明它能完成本组织的已测操作，不能反推凭据的排他资源范围。

本轮通过范围是 **CNB 仓库初始化**。未写入 Secret 内容、推送代码、触发构建、调用 TAT 或部署生产；两台主机和既有业务流水线未作变更。两个验证仓库保留，自动构建开关最终关闭。新账号完整自动接入、Secret 保存和新一轮部署/恢复仍须按各自范围验收。
