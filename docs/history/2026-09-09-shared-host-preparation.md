# 第二项目共享主机：接入准备验证

截至 2026-09-09，第二个项目 FinAgentCrm 已完成本机适配、云资源配置和原生 Caddy 入口恢复验证，**尚未安装或发布到服务器**。既有 FinAgent 仍运行原版本；本记录不能作为新项目共存成功或提速证据。

## 本轮新增的可复用能力

运行包 `0.2.0-preview.4` 支持同一所有者在已有原生 systemd Caddy 主机上追加项目：检查生成式站点与运行配置，绑定授权、恢复及凭据审阅，在管理员事务中追加固定路由，保留已有配置。普通发布程序没有 Caddy 修改权限。未知配置或第三方漂移仍阻断。

另外补齐同域 Web/API/H5 网关、服务及基础设施资源上限、普通应用角色使用预装 vector 扩展、私密业务配置的首装传入，以及相同输入的安装续接。生成器沿用项目已有状态文档，避免多份记录。

## 暴露的问题

- 本机 `docker login --config <不同目录>` 自动使用同一个 macOS 钥匙串，后一次只读登录覆盖推送时使用的账号，造成推送失败。改用独立、无 credential helper 的私密文件配置后，真实推送和拉取通过；已清理本次写入共享 helper 的凭据。未记录操作前的个人 helper 内容，因此不声称恢复了其原值。资源策略格式曾调整，最终阻点证据指向凭据选择，不能将格式调整独立宣称为根因修复。
- 本机默认 Python 缺少生成器依赖，已使用项目私密工具环境。模拟子进程、权限及输出的测试不能假设执行环境的 PATH、umask 或进程退出时序。
- 新项目仍需真实业务输入及容量验收；演示账号、缓存构建和静态空闲资源均不能代替。
- 未筛选的容器盘点包含启动命令，读取时把已有测试 Redis 密码带入工具输出。测试环境凭据审阅已失效，须完成轮换后重新检查；生产密码未进入该输出。此为执行错误，已补充字段白名单要求，不能因原始文件放在私密目录就认为可以直接展示。
