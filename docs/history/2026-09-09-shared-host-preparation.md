# 第二项目共享主机：接入与更新验证

截至 2026-09-11，第二个项目 FinAgentCrm 已完成测试发布、真实接口业务和业务数据隔离恢复。手机页面及 Web 启动问题修复后，普通更新、真实页面与功能共存验收均通过。生产主机尚未安装本项目。以下分阶段保留实际结果，不能将局部耗时作为首次接入提速证明。

## 本轮新增的可复用能力

运行包 `0.2.0-preview.4` 支持同一所有者在已有原生 systemd Caddy 主机上追加项目：检查生成式站点与运行配置，绑定授权、恢复及凭据审阅，在管理员事务中追加固定路由，保留已有配置。普通发布程序没有 Caddy 修改权限。未知配置或第三方漂移仍阻断。

另外补齐同域 Web/API/H5 网关、服务及基础设施资源上限、普通应用角色使用预装 vector 扩展、私密业务配置的首装传入，以及相同输入的安装续接。生成器沿用项目已有状态文档，避免多份记录。

## 暴露的问题

- 本机 `docker login --config <不同目录>` 自动使用同一个 macOS 钥匙串，后一次只读登录覆盖推送时使用的账号，造成推送失败。改用独立、无 credential helper 的私密文件配置后，真实推送和拉取通过；已清理本次写入共享 helper 的凭据。未记录操作前的个人 helper 内容，因此不声称恢复了其原值。资源策略格式曾调整，最终阻点证据指向凭据选择，不能将格式调整独立宣称为根因修复。
- 本机默认 Python 缺少生成器依赖，已使用项目私密工具环境。模拟子进程、权限及输出的测试不能假设执行环境的 PATH、umask 或进程退出时序。
- 新项目仍需真实业务输入及容量验收；演示账号、缓存构建和静态空闲资源均不能代替。
- 未筛选的容器盘点包含启动命令，读取时把已有测试 Redis 密码带入工具输出。此为执行错误，生产密码未进入该输出。已补充字段白名单要求，不能因原始文件放在私密目录就认为可以直接展示。原测试凭据审阅已撤销，后续维护及重新审阅见下文。

## 2026-09-10：测试凭据维护收尾

用户批准后，仅轮换既有项目测试 Redis 凭据并重建其 Redis/API，保留原镜像、数据卷和公开发布身份；其他服务及生产未变更。新密码认证成功、旧密码被拒绝，真实 Redis 备份在隔离容器恢复并下载到本机校验摘要；维护前 keyspace 为空，因此不是非空 Redis 数据恢复案例。维护后 18 项业务检查通过，重复验证未再次轮换。

首个尝试在末尾 `docker top` 检查时因缺少 PID 列失败，已回滚并核验；修正检查参数后成功。40.249 秒仅为成功维护事务，不含准备、首轮失败和业务验收，不能用于声称整体部署提速。

Skill 首装模板改为受保护的 Redis 配置文件及 `REDISCLI_AUTH` 健康检查，密码不再进入进程参数。新项目双环境包已重新生成，控制器、策略、Compose 发布定义和 TAT 保持不变；已有部署不能通过重跑首装获得此修复。模板执行行为、真实容器启动和生成器均已验证。重新盘点的 Caddy 与原恢复证据一致，新凭据审阅绑定真实轮换及业务回执；旧撤销记录保留且仍被安装入口拒绝。

## 首装接续

用户补齐管理员账号后，真实首装发现并修复了三处跨项目兼容问题：管理员 SSH 账号不能与项目发布账号绑定；同域的多个服务身份应映射到已声明的统一网关；空库检查须准确区分预装 vector 扩展对象和业务对象。最后一项已在固定摘要的真实 PostgreSQL 16 中验证：只含 public.vector 可继续，业务表、函数、类型、schema、对扩展的普通依赖及其他扩展仍阻断。首装续接保留已创建的 PostgreSQL/Redis，固定入口返回 ready 并取回安装原文；这不是业务发布成功。
