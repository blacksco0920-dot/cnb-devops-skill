# TCR 初始化与测试环境收尾

## 改动与复用边界

承接[陌生项目实测](2026-09-11-unfamiliar-project-adoption.md)中仍需临时编排的两项工作，增加管理端固定入口：

- `configure-tcr.mjs`：离线预览、Personal 私有仓库与两角色身份初始化、写前记录及续接；显式核验既有资源时只读。
- `verify-test-deployment.mjs`：按冻结的运行包验证已完成测试执行、候选原文及 TAT 回执；不启动部署。
- `reconcile-project-state.py`：分别接纳测试和生产回执，复用已声明的验收结果，更新原状态文档；生产原有验证约束保留。

TCR 操作说明改为固定入口，由 AI 准备参数和凭据。README 保留使用者需要知道的范围和结果，技术契约集中在按需参考文档。此次未改变运行包或线上控制器，无须重新安装主机。

## 真实验证

使用同一 wxseo 独立测试环境已有资源，应用提交仍为 `f377433bfff08c2a1797a40379257458677fe081`，构建 `cnb-87k-1k284qsnm`，TAT `inv-s8hvbsgnap`。本次没有云端创建、密钥轮转、镜像推送或重新发布，也没有新增用户操作。

TCR 只读入口核验了三个精确私有仓库、两种专用身份、组和有效策略、密钥与文件绑定。实测发现 STS 查询缺少地域参数会返回 MissingParameter，补齐并通过回读。此次初始化、Registry 登录和推拉状态明确未检查；此前实际 CI/主机的推拉证据属于原演练，不冒充新入口执行结果。

测试入口读取真实固定命令及精确 TAT 任务，核验已保存的 annotated Tag、候选和原部署回执，通过后重复执行离线复用。第一次发现本机固定包只有依赖清单而未安装 SDK；改用已有锁定 SDK，并补充明确的依赖缺失错误。当前远端 Tag、annotations 和此刻运行状态不由历史回查证明。

收尾引用原演练的 59 项业务检查、4 项登录页面入口检查、116 项共存检查及 PostgreSQL 离机恢复，不重新执行这些检查。业务旧结果缺少统一顶层身份：先核验预期及实际 API/Web 身份、原检查和运行证明，再保留原文路径/摘要与字段映射，生成收尾所需回执。旧私密 discovery 的 project 原为源码目录；保留原始字节和 source_project_dir，经仓库、执行目录、固定包和候选交叉核验后规范为部署标识，严格校验没有放宽。

原 `PROJECT_STATE.md` 添加受管测试段，原文和历史证据保留；私密状态写入对应环境 current。再次执行收尾返回 reused，状态与文档字节不变。观测时间仍为原共存回执的时间，不能将历史检查写成刚刚重新验收。

## 审查与限制

独立子智能体审查并复现修正了安装符号链接启动、一次性密钥先保存后检查元数据、命名空间模糊查询、在线 SDK 调试输出、证据目录并发占用及重复读取旧模块等问题。行为测试覆盖 API 边界、真实私密文件、拒绝路径和重复执行；它们不等于新建云资源的实测。

新 TCR 创建路径尚未用全新资源验证，掉电恢复未测试。当前只支持 Personal / ap-guangzhou；已有凭据不匹配显式契约时不自动重置。此次也未验证生产、真实短信/付费模型、COS 备份恢复、完整浏览器业务、持续负载或不可信租户隔离。两项固定入口减少了临时编排，但没有重新计量陌生项目首次接入总时长，不能承诺整体提速。
