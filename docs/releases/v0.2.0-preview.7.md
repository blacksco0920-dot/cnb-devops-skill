# v0.2.0-preview.7

[中文首页](../../README.md) · [English README](../../README.en.md)

## 中文

本版将公开仓库改为从私有开发仓库导出的独立 Skill 发行快照。既有公开提交和 Tag 保留，仓库地址不变。远端是否已发布以 [GitHub Releases](https://github.com/blacksco0920-dot/cnb-devops-skill/releases) 为准，本地准备完成不代表已经发布。

### 本版变化

- 公开快照保留完整可运行源码、脚本、模板、依赖锁、技术参考、来源和许可证；使用时不依赖私有仓库或 Git 历史。
- 开发过程、完整历史报告和内部测试留在开发仓库；公开包提供[验证摘要](../../references/validation-summary.md)、[共存输入示例](../../references/coexistence-examples.md)、`skill-release.json` 文件清单及独立校验入口。
- 公开 Issues 和 Pull Requests 继续接收反馈与贡献；维护者在开发仓库集成和验证，随下一次发行导出。全部公开可运行源码继续按 MIT 分发，第三方依赖保留各自许可证。
- 中英文首页说明安装、发行和贡献方式；运行包清单统一已确认的 MIT 授权状态，并将历史证据入口改为公开摘要。

### 安装与校验

让 AI 优先安装固定 Tag `v0.2.0-preview.7`，记录解析后的完整提交和实际 Skill 路径。下载该 Tag 的源码归档，或使用浅克隆获取发行快照：

```sh
git clone --depth 1 --branch v0.2.0-preview.7 https://github.com/blacksco0920-dot/cnb-devops-skill.git
cd cnb-devops-skill
python3 scripts/verify-skill-package.py .
```

独立校验只需 Python 标准库，不需要 Git 或私有开发文件；正常执行 Skill 仍须满足[首页依赖](../../README.md#开始前需要什么)。完整克隆仍会下载已有公开开发历史；本次没有重写或移除旧提交。发行清单用于文件、来源和摘要追溯，不能替代真实部署验收。

### 版本与验收边界

本版 Skill 为 `v0.2.0-preview.7`，随附运行包仍为 `0.2.0-preview.5`。本次发行分层不修改部署运行程序；清单中的说明和文档摘要变化不等于主机升级，也不改变历史证据对应的固定提交、候选和安装锁。既有主机无需因此重新首装。

支持范围仍为 PostgreSQL 16、可选 Redis 7、Ubuntu 24.04 / Linux amd64、Docker Compose；完整管理端需要类 Unix 环境、Node.js 22、Python 3.12+、Git/SSH，恢复需要本地 Unix socket Docker。当前实操主要为 macOS/Codex；原生 Windows 不支持完整入口，其他本地环境及 AI 工具的端到端首接尚未验证。无数据库和其他数据库项目不支持当前固定首装路线。

TCR 新建入口只支持 Personal / ap-guangzhou；既有资源只读回查通过，使用该新入口创建全新资源尚未实测。TAT 发布身份的密钥签发仍由 AI 按文档调用 API；必要的用户登录、Secret Web 保存和生产审批继续保留。全新账号接入、外部新手独立使用和整体提速没有新增验收。共享主机不证明持续负载或跨信任租户隔离；恢复仅覆盖每次声明并实际验证的数据，不包括整机、运行秘密或未经验证的外部存储。具体历史范围见[公开验证摘要](../../references/validation-summary.md)。

## English

This release makes the public repository a self-contained Skill distribution exported from a private development repository. The existing repository address, public commits, and tags remain. Check [GitHub Releases](https://github.com/blacksco0920-dot/cnb-devops-skill/releases) for publication status; local preparation alone is not a remote release.

The snapshot includes all runnable source, scripts, templates, dependency locks, technical references, provenance, and licenses needed to use the Skill independently. Development records and internal tests remain in development. The public package includes a [validation summary](../../references/validation-summary.md), [offline coexistence examples](../../references/coexistence-examples.md), the `skill-release.json` manifest, and a standalone check:

```sh
python3 scripts/verify-skill-package.py .
```

The check uses only the Python standard library and does not require Git history or private files. Normal Skill operation still requires the dependencies in the [README](../../README.en.md#what-you-need). Install the fixed `v0.2.0-preview.7` tag using its source archive or the shallow-clone command above, and record the resolved commit and installation path. A full clone still retrieves the existing public history; this release does not rewrite it.

Public Issues and Pull Requests remain the contribution channels. Maintainers integrate and validate contributions in development, then publish them in the next export. All public runnable source remains MIT licensed; third-party licenses are preserved.

The Skill release is `v0.2.0-preview.7`; its runtime bundle remains `0.2.0-preview.5`. The distribution change does not alter deployment runtime code. Metadata and documentation hash changes do not upgrade installed hosts or validate new artifacts. Existing hosts do not need reinstallation for this change.

The fixed path still targets PostgreSQL 16, optional Redis 7, and Ubuntu 24.04 / Linux amd64 with Docker Compose. Full local execution requires a Unix-like environment, Node.js 22, Python 3.12+, and Git/SSH; recovery requires Docker through a local Unix socket. Hands-on use has mainly been with macOS/Codex. Native Windows is unsupported by the full workflow, and end-to-end onboarding in other local environments or AI tools remains unverified. Database-free projects and other databases are outside the fixed setup path.

The new TCR initializer supports Personal / ap-guangzhou only; live checks covered existing resources, not fresh creation through that entry. TAT AccessKey issuance still follows the documented API procedure. Personal login, required Secret Web saves, and production approvals remain. There is no new acceptance for fresh accounts, independent novice use, or overall setup speed. Shared-host checks do not establish sustained load or cross-trust tenant isolation. Recovery covers declared and reconciled data, not whole hosts, runtime secrets, or unverified external stores. Historical acceptance limits remain in the [public summary](../../references/validation-summary.md).
