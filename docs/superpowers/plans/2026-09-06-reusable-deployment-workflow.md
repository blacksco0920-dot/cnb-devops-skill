# 高复用部署 Skill：整体方案与实施计划

状态：规划，尚未实施。2026-09-06；当前 Skill 基线 `db9826a`。

**目标：**兼容范围内的新项目，用同一套经过验证的代码和流程完成接入；AI 主要识别项目、填写配置和解释异常，日常构建、Tag 和部署由流水线完成。

**架构：**Skill 随包提供版本化的流水线模板、调用端、服务器发布器和安装维护脚本。项目只维护差异配置与必要的业务适配；核心代码按固定版本进入业务仓库和服务器，升级时核对差异，不运行时追踪 Skill 最新版。

**技术范围：**先支持 CNB、TCR、腾讯云 TAT、Ubuntu 24.04、Docker Compose、PostgreSQL；沿用已有 Bash、Python、Node.js 与腾讯云官方 SDK，固定依赖。构建可运行任意项目自己的构建命令，不把业务语言固定为 Node.js。文件、命令行、Git/HTTP 是最低工具能力，浏览器自动化可选。

## 1．选择与边界

| 方案 | 结果 | 决策 |
| --- | --- | --- |
| 继续补规则和示例 | 阅读后仍要现场开发执行器 | 不足以达到目标 |
| 建独立平台、控制仓库和通用插件框架 | 增加安装、权限和维护成本 | 不作为默认路线 |
| 随 Skill 分发可执行工件，项目配置驱动 | 公共逻辑维护一次，新项目复用固定版本 | 本计划采用 |

优先兼容普通多服务 Compose 应用，既覆盖单项目独立 PostgreSQL，也覆盖已有共享 PostgreSQL 的独立库/用户。第二种仅在共享主机已有验收和项目开通记录时复用；不由日常发布接管共享基础设施。Redis、上传卷按项目声明保留，备份恢复证据按存储类型分别记录。

首版不扩展 Kubernetes、多云发布平台、任意数据库迁移 DSL 或全局控制服务。支持范围外的问题要在首次盘点阶段明确，不在接入途中偷偷扩展框架。既有项目不因采用新 Skill 而自动迁移 registry、重装系统或替换生产流程。

## 2．已知来源与缺口

| 能力 | 已有来源 | 提取原则 |
| --- | --- | --- |
| GitHub→CNB 同 SHA 同步 | ecat `.github/workflows/sync-cnb.yml` | GitHub 源项目使用；CNB 原生项目跳过，不强制所有项目经过 GitHub |
| CNB→TCR→TAT→测试→候选 | ecat `.cnb.yml` 及 `deploy/` | 提取已运行的阶段与脚本依赖，保留实际验收绑定 |
| 服务器日常发布 | ecat `tat-command.sh`、`tat-deploy-test.py`、Compose | 优先外置服务、路径、镜像和探针常量，保留已有事务与校验行为 |
| CNB 候选页面和门禁 | ecat Tag/manifest/gate 程序 | 作为现成实现提取；其新生产入口仍禁用，不能直接当成生产完成品 |
| 生产执行及数据库恢复 | FinAgent 受控生产演练代码与回执 | 提取已验证部分，不整体搬入其独立控制仓库和临时辅助程序 |
| 首次安装、升级及审计命令 | 部分历史说明、未完整版本化脚本 | 有界追溯一次；能核对的保存来源，找不到的按明确安装目标补齐并实际验证 |
| 共享 Caddy 与主机盘点 | 当前 Skill 的现有工具 | 仅在匹配拓扑时复用，不重做已验收维护 |

ecat 核对代码基线为 `f52eb1ddf928729b3a4db23d8b0de9211984c4d9`，记录的测试成功候选属于自己的较早提交；不把该 HEAD 说成已部署。生产只读预检模板引用的服务器程序目前未找到，独立恢复源码存在但未启用。这些都作为明确缺口，不用占位脚本冒充可执行能力。

## 3．真正交付什么

拟在 Skill 内增加一个完整、可复制的目录；以下为计划路径，尚未创建：

```text
SKILL.md                         短入口：接入、发布、恢复、升级
README.md                        人看的流程、前提、配合动作和验收结果
references/standard-workflow.md   AI 的阶段说明与差异适配规则
references/bootstrap.md           首装、项目开通、升级的职责与恢复条件
assets/cnb-tcr-tat/
  bundle.json                    包版本、来源、兼容范围、文件校验值
  project.schema.json            项目差异配置的可检查边界
  project.example.yml            无秘密输入示例，AI 填写
  templates/                     CNB、可选 GitHub 同步、Compose、TAT 命令
  ci/                            TAT 请求/调用、候选生成/校验等复用代码
  host/                          发布、只读检查、恢复及安装维护代码
  dependencies/                  执行依赖清单与固定版本
scripts/prepare-project.py       读取项目配置，校验并生成变更预览/文件
scripts/configure-tat.mjs        经授权创建或核对固定命令，输出命令清单
```

工具仅完成本 Skill 的具体任务，不增加独立客户端服务或新的远程平台。优先复制/提取原实现；只有被多个阶段使用且已有需要的代码才拆成公共模块，不先大规模重构 ecat 发布器。

业务项目的约定输出：

```text
deploy/project.yml              唯一手工维护的非秘密部署差异配置
deploy/vendor/cnb-devops/        固定版本核心、模板生成物及来源锁定记录
deploy/hooks/                   确实需要的项目专属探针/适配
.cnb.yml                        生成的 CNB 原生流水线
.cnb/tag_deploy.yml              生成的原生候选发布页面
docs/DEPLOYMENT.md               稳定操作入口及拓扑
docs/PROJECT_STATUS.md           当前阶段、证据和下一动作
```

不重复创建另一份手填服务清单。配置只表达项目/分支、服务及 Dockerfile/上下文、镜像命名、端口、变量引用、健康/业务探针和选定迁移方式。已有 Dockerfile 不强制重写。

密码和云目标绑定进入批准的 Secret/主机控制边界；生成器只使用引用和非秘密配置。构建命令由 CI 执行；主机迁移和业务探针若需项目代码，须先作为固定部署工件审阅安装，不能由一次发布请求传入任意 shell、路径或目标。

自动生成文件和核心文件不得成为第二套人工配置。发现项目手改核心时，升级输出差异并停止覆盖；由维护者选择合并修复或迁移到配置/项目适配。各项目可以停留在不同已验证包版本，不建立后台同步服务。

已有 `.cnb.yml` 中不属于本包的任务必须保留；无法可靠合并时输出变更预览，不覆盖整份文件。配置中的服务数量决定镜像映射和预期身份，不能保留 ecat 的固定四服务、九请求假设。

## 4．三种工作流

| 场景 | 执行内容 | 复用与完成标志 |
| --- | --- | --- |
| 新账号＋新服务器 | 收集必要选择→准备账号权限材料→检查 TAT/网络/预装组件→安装依赖与受控执行器→开通项目→首次流水线 | 首装脚本、命令内容和读回结果可追溯，不靠未保存的临时 TAT 命令完成 |
| 已接通环境新增项目 | 读取既有主机能力→验证仍适用→生成本项目配置→开通独立路由/数据/权限→首发 | 不重装公共组件；只增加本项目范围，不继承其他项目的授权或凭据 |
| 日常发布 | Git push→CNB 检查/构建→TCR→固定 TAT→测试验收→自动 Tag→就绪/审批→同 digest 生产→验收 | 不改核心脚本，不手工拼候选，不重放初始化；失败按当前阶段继续 |

首次安装、项目开通、升级、日常发布、恢复分别有固定入口和权限。安装脚本要能检测已完成状态，重复调用无漂移时不改动；版本或现场不兼容时给出准确差异，不自动覆盖。初次管理员权限不能进入日常发布凭据。

TAT 命令使用可重建的版本化名称与精确内容摘要。配置工具先查询；同一内容已存在就复用并验证绑定，未知同名内容阻断。升级创建新的已验证命令/控制器版本，再切换绑定，保留回退材料；不把线上命令静默改成新逻辑。

主机安装从已批准、国内可达的固定版本地址获取无秘密代码包，校验摘要后执行；不能下载可变 main 后直接运行。数据库/JWT 等能在主机生成的值直接生成；必须导入的私密配置，复用管理员已有的受保护通道，例如经授权的 SSH/SFTP 或本人云终端输入。首次盘点就确定该通道，不在中途临时研发凭据网页或传输协议。此管理员首装通道不进入日常 CNB 发布，TAT 命令正文和日志不得包含明文秘密。

## 5．工具与人的分工

| 工作 | 默认负责人和方式 |
| --- | --- |
| 识别项目、生成文件、准备权限和操作材料 | AI 使用项目文件及命令行；先完成可审阅材料 |
| CNB Git、TAT 命令管理与执行结果查询 | 经授权的脚本和官方 API/SDK；不依赖浏览器插件 |
| 账号实名、验证码、缺少可用 API 的配置 | 人完成；材料按依赖批次交付，不把技术设计交给人 |
| CNB Secret 文件编辑 | 按平台规定由人在 Web 完成，AI 给出文件结构、引用范围与验收动作 |
| 生产审批 | 按项目政策批准具体候选；其余技术记录由固定程序形成 |

腾讯云提供 CreateCommand、DescribeCommands、InvokeCommand 和结果查询等 API，可以将命令配置与调用做成脚本。[TAT API 概览](https://cloud.tencent.com/document/api/1340/52696)

CNB 当前要求 Secret 文件通过 Web 编辑，不能本地 clone/push；因此承诺的是“不依赖 AI 自动控制浏览器”，不是“所有账号配置都能无人工完成”。[CNB Secret 文档](https://docs.cnb.cool/zh/repo/secret.html)

生产首版优先提取 FinAgent 已验证的 CI 外执行授权与主机验签路径，做成包内一个固定模式，完成针对新包的实测后再发布；不开发多套审批插件或新增签名服务。不能仅凭分仓或普通 CI 可改写的字段推定安全，也不要求每个项目重写签名逻辑。用户完成项目规定的具体候选审批，固定程序负责技术授权记录；已有其他可信发布路径的项目保持原状，迁移单独定范围。

## 6．实施顺序与每阶段交付

### P0：冻结来源和兼容范围

- [ ] 在 `assets/cnb-tcr-tat/bundle.json` 建立来源清单：提交、所需文件/依赖、真实验收范围、缺失项；先确认可随开源包分发的代码归属和依赖许可。
- [ ] 核对 ecat 的调用端→命令模板→主机程序→Compose→探针完整依赖；一次性维护脚本只做一次有界历史追溯，不加载整个旧会话。
- [ ] 列出允许进入 `deploy/project.yml` 的差异；不支持的能力在入口明确退出快速路径。

完成条件：无需再打开 ecat 或旧会话才能理解交付包的文件来源、运行依赖和缺口；尚缺的代码不计作完成。

### P1：先交付可复用的测试发布与候选包

- [ ] 提取 `.cnb.yml`、TCR 摘要、TAT 调用、服务器发布器和候选程序到上述 bundle；先外置项目常量，保留已验证的事务逻辑。
- [ ] 实现 `prepare-project.py` 的配置校验、确定性生成和已有文件差异预览；只有明确应用操作才写文件，生成器本身不操作云端。
- [ ] 复用构建环境已有的依赖/镜像缓存及国内可达的软件源；分别记录冷、热构建，不用缓存替代同提交检查或不可变镜像身份。
- [ ] 在两个服务数量/命名不同的本地项目验证：只改配置和必要业务探针，核心文件校验值一致，能产生原生 CNB 流水线和候选阶段。

完成条件：新项目无需重新开发发布器，依赖完整随包提供；合法配置可运行，错环境、缺镜像、可变 tag、失配回执被实际拒绝。此阶段不宣称生产完成。

### P2：补齐全新环境安装、项目开通和升级

- [ ] 在 `host/` 中保存可回读的初始化/项目开通/升级工件，安装包校验值与固定 TAT 命令清单对应。
- [ ] 实现 `configure-tat.mjs` 的查询复用、内容验证、新版本创建及受控绑定切换；不把管理员凭据交给普通流水线。
- [ ] 从干净测试主机完成安装，再重复同一操作验证不重装、不重复建命令；在已有共享能力的主机验证仅开通新项目范围。
- [ ] 对中断安装和核心被手改的情况验证准确停止与续接，避免重新申请账号、令牌和整机重装。

完成条件：全新服务器的接入不依赖临时文件、浏览器上传或旧服务器导出；安装命令与实际结果都有对应源码和记录。

### P3：补齐生产晋级与恢复，不另造第二套发布系统

- [ ] 对照 FinAgent 已验证的生产执行/恢复路径，把环境差异收敛到同一包；首发空库和后续更新采用明确模式，不推断数据库可回退。
- [ ] 接通候选的生产就绪、可信审批、固定 apply 及独立执行核验；测试和生产完整镜像摘要一致，生产不能重新构建。
- [ ] 包含真正的备份传输、校验与隔离 PostgreSQL 恢复程序；定义已声明其他持久存储的备份方式及验收范围。
- [ ] 验证失效审批、错误目标、跨项目请求、迁移后失败、备份损坏与恢复中断；不以“页面有按钮”或 archive 可读代替成功。

完成条件：完整新账号演练有生产和恢复实证；应用租户权限或外部接口未通过时，只报告部署演练结果，不承诺真实业务可用。

### P4：用实际复用结果验收，再收敛文档

- [ ] 在明确授权的目标上，完成一轮全新账号/服务器接入和第二项目接入；项目 A/B 的服务集合及至少一项数据库/迁移方式有真实差异。
- [ ] 用只有文件、终端和 Git/HTTP 的新会话复现，关闭浏览器自动化；第二个支持该能力基线的工具执行本地生成/续接验证，云端步骤单独记录范围。
- [ ] 核对下面的效率指标及完整验收矩阵；没有达到时修实际重复工作，不增加流程平台或为指标编写新监控系统。
- [ ] 把最终使用方式收敛到 README、标准工作流和两份项目文档；本计划完成后归档一次，不留下多套当前状态。

完成条件：两项目均没有修改公共发布核心来“临时跑通”；外部安装者只拿 Skill 包即可运行兼容路径，不需要维护者本机目录。

## 7．复用与速度如何验收

以下是工程目标，尚非已实现的耗时承诺。首次部署可能受镜像构建、主机网络和本人验证影响，必须分开计时。

| 指标 | 验收目标 |
| --- | --- |
| 核心复用 | 兼容项目接入时公共核心文件修改数为 0；差异只在配置和必要业务适配 |
| 第二项目适配 | 不新增一套部署控制器，不复制其他项目的目标、数据或权限；服务数量改变由配置处理 |
| 已有镜像构建条件、账号及主机准备好 | AI 完成配置和接入准备的主动工作时间目标 10–15 分钟；云构建/传输/人工等待另计 |
| 日常发布 | 部署定义不变时新增发布代码为 0；测试 push 自动走到候选，只保留必要的生产审批 |
| 人工交接 | 按依赖集中给出材料，一项已完成动作不重复要求；每次介入记录原因，不能隐去扫码或手工操作 |
| 会话续接 | 仅靠项目两份文档、锁定工件和受保护证据位置恢复当前阶段，不读取旧聊天 |
| token 成本 | 工具可提供则记录真实用量，固定项目/工具/模型比较；缺失则标未采集，不用猜测数据证明降本 |
| 文档与脚本验证 | 优先沿用来源测试；新增测试覆盖变化的实际行为，不用字符串存在性或测试数量表示复用成功 |

完整验收矩阵必须分列：首装、新增项目、测试部署、自动候选、生产晋级、数据库恢复、升级与中断续接。一次简单页面上线不能替代这些结果。

## 8．执行约束

本计划不修改或接管当前 ecat、FinAgent 线上环境。后续真实云验证先形成可审阅的目标与操作范围，按已有有效授权执行，缺少范围时仅补充必要授权。实现默认按 P0→P1→P2→P3→P4 推进，每阶段有独立可验证产物；不要并行创建互相依赖的另一套控制器。
