# 对外介绍与首次使用优化

依据用户已确认的六点分析实施：让外部使用者理解交付结果，让 AI 独立复用执行包，将来源和演练经历留在维护者记录。

## 设计与边界

- README 面向使用者；SKILL 与 references 面向 AI；history 和来源记录面向维护者。
- 默认两台独立主机；已有复杂共享主机按实际条件进入专门流程。
- 完整通用配置覆盖测试、生产与恢复，保留最小生成示例；业务构建和验收仍需按真实项目适配。
- 本轮不操作云、不继续第 4 轮、不修改业务仓库或运行程序；保留授权、审批、数据与恢复门禁。
- 保留真实来源与固定版本证据；不把单次耗时作为任意项目承诺，不把多项目复用等同于共享主机。

## 验证说明

两名独立审阅者走查了仅测试首次接入、第二个独立项目、完整双环境配置及历史引用范围。已修正仅测试误需生产目标、空库初始化与已有数据迁移混淆两处歧义。

配置回归实际执行生成器，核对完整双环境的首装、Caddy、生产事件和恢复策略；生产公钥待填时必须拒绝，重复生成保持不变。文档密钥命令另在临时目录执行，验证公钥格式及不覆盖已有密钥。

旧检查中硬编码的原句改为分层链接检查；链接工具补齐显式锚点和目录链接支持。固定测试时间改用同值的 UTC 日期构造，避免敏感标识扫描误报。运行程序、既有云端验证提交和摘要保持原样，本轮检查不作为新增云端验收。

最终检查：Python 离线回归通过；7 项需要显式本地 PostgreSQL/Caddy 镜像的集成用例未启用。Node 接口回归、文档链接、Skill 格式和包摘要检查通过。未执行新增云端发布或恢复。
