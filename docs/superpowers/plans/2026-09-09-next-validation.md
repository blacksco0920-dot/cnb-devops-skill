# Deployment Efficiency and First-use Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development for independent read-only review, or executing-plans for sequential execution. Follow the checkboxes and preserve actual evidence.

**Goal:** 验证固定入口能否减少日常发布的操作开销，再验证陌生项目与无历史上下文执行者能否独立完成首次接入。

**Architecture:** 沿用 CNB → TCR → TAT、现有生成器和两个本机续接入口。先验证已有环境，再验证新项目；只针对观察到的阻塞做最小修复，不增加新的编排平台。

**Tech Stack:** 当前 Skill、Node.js 22、Python 3.11+、Git、SSH、Docker、CNB 与腾讯云现有接口。

## 当前依据

- 实测版本：`3b9f3c9`。生产入口、恢复入口、安装符号链接及独立示例检查已通过；2026-09-09 已完成新入口真实双环境验收，见[本轮报告](../../history/2026-09-09-resume-entry-live-validation.md)。
- [上一轮日常发布](../../history/2026-09-08-api-release-rehearsal.md)完整墙钟为 39.91 分钟，覆盖测试构建、同镜像生产、双环境业务和离机恢复。主要已知开销为依赖遗漏、临时主机采集及阶段衔接。
- 既有三轮重装演练已由用户结束；本计划不恢复剩余轮次。
- [当前入口验证结果](2026-09-09-release-resume-entries.md#验证结果)与云端成功、首装复用和效率证据分别记录。

## Global Constraints

- 用户已批准推进。本计划按真实执行更新；执行时核对有效的项目、环境与候选授权，不从计划文字推导额外授权，也不重复索取已有有效授权。
- 第一阶段沿用已验收的活动运行包，不混入主机重装、控制器升级或新账号初始化。若新入口与活动包存在兼容缺口，明确记录并单独解决，不隐式换包。
- 构建、业务、审批、恢复范围不为压缩耗时而缩减。生产使用测试过的同一组镜像摘要；恢复对账覆盖声明的数据范围。
- 公开材料只保留时间、步骤、链接、摘要和结论。凭据、签名私钥、备份及私密路径留在受保护记录中。
- 真实演练先做一轮；只有失败、新修复或未解决疑点才安排必要复测。无新问题时不重复验证已通过项。

**Files / outputs:** 执行项目现有 `docs/DEPLOYMENT.md`、`docs/PROJECT_STATUS.md` 和私密阶段记录；完成后新增 `docs/history/2026-09-09-resume-entry-live-validation.md`，写实际执行日期，并更新 `docs/history/README.md` 的证据索引。

**Consumes:** 已批准项目与目标、有效凭据、已接受安装记录、活动包摘要、完整应用提交、现有业务验收程序。

**Produces:** 测试与生产运行证据、两环境业务及隔离恢复回执、阶段时间轴、接续结果、最小修复记录。

- [x] 只读核验入口与活动包兼容性、目标身份、项目状态和权限有效性；归集缺口，避免执行到中途才发现依赖缺失。
- [x] 在第一项准备动作前记录开始时间。记录 Skill/活动包/应用版本及缓存条件；因缺权或环境不满足而停顿也保留在时间轴上。
- [x] 按项目政策推进一次正常测试构建。完整提交与构建 ID 已知后，用 `release-session.mjs prepare` 提前准备生产依赖，并预检恢复参数和本机 Docker 条件。
- [x] 测试与业务通过后，按受控分支、原生就绪、本机 `candidate/sign/publish`、原生批准的现有流程完成同镜像生产发布。
- [x] 在一次自然等待点交给无历史上下文执行者，只提供 Skill、项目目录和私密记录索引；它应从状态及实时证据确认下一动作，不重做已完成步骤。交接过程不得通过聊天复制凭据。
- [x] 用 `rehearse-recovery.py` 分别完成授权范围内的两环境导出、下载、隔离恢复与数据核对。安全完成后再运行状态/重复调用检查，验证复用已有结果；不为测试中断而终止正在停写、迁移或恢复的操作。
- [x] 汇总结果并核验源服务已恢复、生产身份正确和隔离恢复结束状态。记录失败及修复所在步骤；只有出现缺陷才补对应回归，不以新增检查数量代替实测。

**功能验收：**全范围通过；本机固定入口真实执行；无任务专用采集/签名/恢复包装脚本；无遗漏依赖导致的失败；续接不重复导出或重新配置有效资源。应用本身必要适配与公共 Skill 缺陷分开记录。

**效率验收：**给出完整墙钟与同范围阶段对照，明确上一轮已知开销是否消失。至少一次整轮成功可以验收新入口可用；只有可比数据支持才宣称提效，不以一次构建缓存波动证明普遍加速，也不预先承诺新项目上线时限。

## 统一计时口径

记录每个阶段的开始、结束、执行者、结果和关联构建/回执：前置检查、测试构建、业务验证、生产准备、分支等待、原生就绪、签名发布、原生批准、生产部署、两环境恢复、收尾。

- **完整墙钟：**从首项准备到最后一项验收证据形成；收尾文档整理另列。
- **平台与本机执行：**保留原始起止区间；并行区间不重复相加。
- **人为操作：**分别记录请求、实际平台动作（若可查）、收到回复的时间，以及动作类型。已有分支规则带来的合并确认不归因于 Skill。
- **衔接与排障：**分别记录无依赖阻塞却未推进的间隔、失败定位和修复时间，给出可归因的减少项。人工等待与并行工作重叠时不简单扣除整段等待。
- **AI 成本：**记录工具调用数、临时新增文件及可取得的本次执行 token 用量；包含子智能体用量且避免重复计数。缺少可靠来源写“未采集”，不能以账号整体用量差代替本次成本。

**Files / outputs:** 目标项目的部署配置、`docs/DEPLOYMENT.md`、`docs/PROJECT_STATUS.md`；Skill 侧记录一份匿名化接入结论，不把业务项目加入运行依赖。

**Consumes:** 当前发布的 Skill、项目源码、业务目标、已授权账号/服务器、必要的安全凭据入口；不提供来源项目配置或旧会话。

**Produces:** 测试地址、实际业务证据、可接续项目文档、复用/适配/缺失清单和人工交接记录。

- [ ] 用无历史上下文执行者从 README 和 SKILL 入口开始。将当前解释与文档不一致之处记录为缺陷，不靠维护者口头补课掩盖。

## 下一阶段执行切片：首次使用与对外交付
