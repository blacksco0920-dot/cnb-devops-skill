# 标准发布与恢复续接入口

用户已要求按 9 月 8 日复测结论优化 Skill。目标是减少 AI 重复拼接命令、遗漏生产依赖与恢复前辅助采集失误；沿用已验收的 CNB → TCR → TAT、候选、签名及恢复协议。

## 选择

采用两个任务明确的薄层执行器：本机生产准备/授权续接，以及单环境离机恢复。只补文档不能消除重复拼接；另建完整发布平台会复制 CI 和主机门禁。新入口调用既有包内程序，不触发重装、主机升级或扩大生产授权。

## 接口和职责

- `scripts/release-session.mjs`：`prepare` 提前补齐生产子包锁定依赖；`candidate` 从 annotations 和标准 Git gate 取得原始候选/就绪材料；`sign`、`publish` 调用原标准程序；`status` 返回当前断点。使用私密 spec 与会话目录。状态不是授权，过期/漂移仍交原门禁拦截。没有隐式 main 合并、原生按钮触发或生产部署。
- `scripts/rehearse-recovery.py`：默认本地预览；`--apply` 串联固定 SSH 前态、标准 export、下载、校验、标准 restore-local 和后态对账。参数选择单项目、单环境、批准的目标/安装锁及精确 commit/build；任何失败停止依赖阶段并保留时间和原始证据。已完成导出可继续下载，结果不明时先核对远端 journal，不能重复停写或盲目重新导出；源恢复保持独立明确动作。
- 现有项目两份文档仍是用户与下一会话的入口，只索引私密会话目录及一个下一动作，不另建公共状态系统。流水线仍负责测试构建/部署/候选和生产实际执行。

## 必须保留的行为

同一候选与输入摘要绑定，原始候选/就绪/签名字节不重序列化；生产凭据分域，输出不包含密钥或完整云响应；本机新签署需要明确生产意图，原生批准保持不变。恢复前完成本机工具/镜像准备，源端只输出选定元数据，使用严格 SSH；恢复仍在不同本机 Docker daemon、无网络/无端口，由原程序对账全部声明数据。

状态文件使用私密目录、原子写入和排他运行锁。完成阶段只有证据存在、摘要和输入仍相符时才可复用；未知写入不自动重试。只统计真实时间，保留失败和等待，不能从局部提速推导整轮提速。

## 验收

依据上一轮真实失败作基线。先写失败用例，再验证两个薄层入口：生产依赖目录选择、候选获取、已有签名续接与过期/漂移阻断；恢复导出一次、下载中断续接、源恢复未确认阻断、摘要错误和标准恢复结果复核。使用合成项目与隔离传输测试，不使用真实凭据、不发布现有应用。检查跨项目参数、私密输出、文档入口和生成包完整性。新增入口本机通过不等于云端新一轮实测通过。
